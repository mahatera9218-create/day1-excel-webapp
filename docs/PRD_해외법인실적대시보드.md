## 1. 제품 개요

### 1-1. 한 줄 정의

로컬 `.xlsx` 실적 파일을 브라우저에서 직접 읽어, 핵심 지표·차트·검색 가능한 데이터 표로 즉시 변환하는 단독 실행형 웹 대시보드.

### 1-2. 제품 원칙

| # | 원칙 | 의미 |
|---|---|---|
| 1 | 업로드 외 조작 없음 | 파일 선택 이후 설정 단계를 두지 않는다 |
| 2 | 데이터는 밖으로 나가지 않음 | 전 과정이 브라우저 내에서 처리된다 |
| 3 | 모르면 숨기지 않고 알린다 | 인식 실패 시 침묵하지 않고 안내 문구를 노출한다 |
| 4 | 원본을 신뢰하되 검증한다 | 합계 행 등 비데이터 행은 자동 배제하고 그 사실을 고지한다 |

## 3. 기능 요구사항

### FR-01. 엑셀 파일 업로드

| 항목 | 내용 |
|---|---|
| 설명 | 사용자가 로컬 `.xlsx` 파일을 선택하여 업로드한다 |
| 입력 방식 | ① 파일 선택 버튼 ② 업로드 영역으로 드래그 앤 드롭 |
| 허용 확장자 | `.xlsx` 만 허용 |
| 처리 위치 | 브라우저 (`FileReader` → `ArrayBuffer`), 서버 전송 없음 |
| 안내 문구 | ".xlsx 파일을 업로드하면 첫 번째 시트를 읽어 표와 차트로 표시합니다. (드래그 앤 드롭도 가능합니다)" |
| 업로드 후 | 파일명을 체크 표시와 함께 노출 |

**수용 기준**
- `.xlsx` 외 확장자 업로드 시 데이터를 갱신하지 않고 오류 문구를 표시한다
- 오류 발생 시에도 **직전에 표시 중이던 데이터는 유지**된다
- 파일 재업로드 시 모든 지표·차트·표가 새 데이터로 교체된다

---

### FR-02. 첫 번째 시트 데이터 읽기

| 항목 | 내용 |
|---|---|
| 대상 | 워크북의 첫 번째 시트 (`SheetNames[0]`) |
| 헤더 탐지 | 상단 15행 이내에서 **채워진 셀이 60% 이상이거나 3개 이상인 첫 행**을 헤더로 판정 |
| 단위 탐지 | 헤더 이전 행에서 `(...원)` 패턴을 찾아 단위로 사용 (미검출 시 `백만원`) |
| 빈 행 처리 | 전 셀이 빈 행은 제외 |

**배경** — 실제 파일은 상단에 제목 배너(1행), 영문 부제(2행), 공백(3행), 그룹 헤더(4행)가 있고 **5번째 행**이 실제 컬럼 헤더다. 고정 위치를 가정하면 파일마다 깨지므로 자동 탐지 방식을 채택한다.

**수용 기준**
- `해외법인_분기실적_2026.xlsx` → 헤더 19개 컬럼, 데이터 120행, 단위 `백만원` 인식
- `발전소별_월간운영_2026.xlsx` → 384행, 첫 컬럼 `월` 인식
- `광양터미널_월간운영_2026.xlsx` → 192행, 첫 컬럼 `구역` 인식

---

### FR-03. 합계 행 자동 배제

| 항목 | 내용 |
|---|---|
| 목적 | 파일 하단의 총계 행이 데이터로 집계되어 수치가 왜곡되는 것을 방지 |
| 판정 조건 | **① 앞쪽 3개 셀 중 하나가 합계 키워드 포함** `AND` **② 행의 빈 셀 비율 20% 이상** |
| 키워드 | `합계`, `총계`, `소계`, `누계`, `total`, `subtotal`, `sum` (대소문자 무시) |
| 사용자 고지 | 표 제목 옆에 "합계 행 N개 제외됨" 배지 표시 |

**두 조건을 함께 요구하는 이유** — 키워드만으로 판정하면 `TOTAL ENERGY CORP` 같은 정상 법인명이 오탐된다. 실제 합계 행은 라벨 외 다수 셀이 비어 있다는 점을 함께 확인한다.

**수용 기준**
- `트레이딩_거래내역_2026.xlsx`의 `💎 ANNUAL TOTAL` 행이 표·지표에서 제외되어 201행 → **200행**
- `해외법인_분기실적_2026.xlsx`는 합계 행이 없으므로 **120행 유지, 배지 미표시**

**알려진 한계** — 빈 셀이 거의 없는 형태로 작성된 합계 행은 탐지되지 않는다.

### FR-04. 핵심 지표 카드

4종의 지표를 카드 형태로 표시한다.

| 카드 | 산출식 | 표기 |
|---|---|---|
| 총 매출 | `연매출` 합계 (없으면 Q1~Q4 매출 합) | 천 단위 컴마 + 단위(백만원 등) |
| 총 영업이익 | `연영업이익` 합계 (없으면 Q1~Q4 영업이익 합) | 천 단위 컴마 + 단위 |
| 평균 영업이익률 | `총 영업이익 ÷ 총 매출 × 100` | 소수 1자리 + `%` |
| 법인 수 | 유효 데이터 행 수 | 정수 + `개` |

> 검증에 사용한 실제 집계값은 사내 실적 정보이므로 본 문서에 기재하지 않는다.
> 산출 결과가 원본 합계와 일치하는지는 자동화 테스트로 확인한다.

**세부 요구사항**
- 천 단위 구분 기호를 적용한다 (`ko-KR` 로케일)
- 평균 영업이익률은 **단순 평균이 아닌 가중 평균**(총이익÷총매출)으로 산출한다 — 규모가 다른 법인의 이익률을 단순 평균하면 소규모 법인이 과대 반영되기 때문
- 매출/이익 컬럼을 찾지 못하면 값 대신 `-`를 표시한다

### FR-05. 지역별 매출 차트

| 항목 | 내용 |
|---|---|
| 차트 유형 | 세로 막대 (BarChart) |
| 분류 기준 | `지역` 컬럼 |
| 값 | 지역별 매출 합계 |
| 색상 | 항목별 순환 팔레트 |
| 상호작용 | 막대 hover 시 지역명·매출액 툴팁 |

**수용 기준** — 해외법인 파일 기준 7개 지역(유럽/아시아/북미/중남미/중동/아프리카/대양주) 막대가 렌더된다.

---

### FR-06. 분기별 매출 추이 차트

| 항목 | 내용 |
|---|---|
| 차트 유형 | 꺾은선 (LineChart) |
| X축 | Q1, Q2, Q3, Q4 |
| 값 | 분기별 전 법인 매출 합계 |
| 표시 | 각 분기 지점에 데이터 포인트 표시 |

**수용 기준** — `Q1매출`~`Q4매출` 4개 컬럼이 모두 존재할 때만 렌더하며, 데이터 포인트 4개가 표시된다.

---

### FR-07. 법인별 영업이익 차트

| 항목 | 내용 |
|---|---|
| 차트 유형 | 가로 막대 (Vertical BarChart) |
| 정렬 | 영업이익 내림차순 |
| 표시 개수 | **상위 15개** |
| 제목 표기 | 전체가 15개 초과 시 "법인별 영업이익 (상위 15개 / 전체 120개)" |

**상위 15개로 제한하는 이유** — 전체 120개 법인을 모두 표시하면 차트 높이가 3,000px를 넘어 비교 기능을 상실한다. 잘라낸 사실은 제목에 명시하여 사용자가 부분만 보고 있음을 인지하게 한다.

---

### FR-08. 검색 및 필터

| 기능 | 사양 |
|---|---|
| 검색 | 전 컬럼 대상 부분 일치, 대소문자 무시, 한글/영문/숫자 지원 |
| 필터 | `지역` 컬럼 기준 드롭다운 (`지역` 없으면 `국가`로 대체) |
| 조합 | 필터와 검색은 **AND 조건**으로 동시 적용 |
| 결과 표기 | 표 제목의 행 수가 필터 결과에 맞춰 실시간 갱신 |
| 무결과 | "표시할 데이터가 없습니다." 안내 표시 |

**수용 기준**
- `QATAR` 검색 → 120행 중 2행
- 지역 `대양주` 필터 → 9행, 표시된 행의 지역이 전부 `대양주`
- `대양주` + `호주` 조합 → 7행

### FR-09. 오류 및 예외 처리

| 상황 | 동작 |
|---|---|
| `.xlsx` 외 확장자 | "⚠ .xlsx 파일만 업로드할 수 있습니다." + 기존 데이터 유지 |
| 파싱 실패 | "파일을 읽는 중 오류가 발생했습니다. 형식을 확인해주세요." |
| 데이터 0행 | "시트에서 데이터를 찾을 수 없습니다." |
| 지표 컬럼 미인식 | 카드에 `-` 표시 |
| 차트 컬럼 미인식 | 차트 자리에 사유 안내 문구 (예: "지역/매출 컬럼을 찾을 수 없습니다.") |
| 업로드 전 | "엑셀 파일을 업로드하면 이곳에 핵심 지표, 차트, 데이터 표가 표시됩니다." |

## 5. 비기능 요구사항

### NFR-01. 아키텍처

| 항목 | 사양 |
|---|---|
| 구성 | 클라이언트 전용 SPA (백엔드·DB 없음) |
| 프레임워크 | React 18 + Vite 5 |
| 엑셀 파싱 | `xlsx` |
| 차트 | `recharts` 2.x |
| 데이터 흐름 | 파일 → `FileReader` → 파싱 → React state → 렌더 (외부 전송 없음) |

### NFR-02. 실행 환경

| 항목 | 사양 |
|---|---|
| 실행 방법 | `run.bat` 더블클릭 |
| 자동 처리 | `node_modules` 부재 시 `npm install` 자동 수행 후 서버 기동 |
| 접속 주소 | `http://localhost:5173` (브라우저 자동 실행) |
| 필요 환경 | Node.js 18 이상 |

### NFR-03. 반응형

| 브레이크포인트 | 레이아웃 |
|---|---|
| 900px 초과 | 지표 4열, 차트 2열(법인 차트는 전폭) |
| 560~900px | 지표 2열, 차트 1열 |
| 560px 이하 | 지표 1열, 헤더 고정 해제, 차트 축 레이블 축소(200px → 92px) |

**모바일 필수 조건** — 페이지 전체에 **가로 스크롤이 발생하지 않아야** 한다. 표는 자체 영역 내에서만 가로 스크롤한다.

### NFR-04. 데이터 보안

| 항목 | 내용 |
|---|---|
| 데이터 전송 | 없음 — 파일이 브라우저 밖으로 나가지 않음 |
| 저장 | 없음 — 새로고침 시 초기화 |
| 인증 | 불필요 (로컬 단독 실행) |

### NFR-05. 품질 기준

| 항목 | 기준 |
|---|---|
| 콘솔 에러 | 0건 |
| 런타임 에러 | 0건 |
| 제공 엑셀 4종 처리 | 크래시 없이 표·검색 정상 동작 |

## 6. 데이터 사양

### 6-1. 표준 입력 — 해외법인 분기실적

| # | 컬럼 | 용도 |
|---|---|---|
| 1 | 법인코드 | 표 표시 |
| 2 | **법인명** | 법인별 영업이익 차트 축 |
| 3 | 국가 | 필터 대체 키 |
| 4 | **지역** | 지역별 매출 차트, 필터 |
| 5 | 사업부문 | 표 표시 |
| 6 | 지분율(%) | 표 표시 |
| 7 | 임직원수 | 표 표시 |
| 8~11 | **Q1~Q4매출** | 분기별 추이 차트 |
| 12 | **연매출** | 총 매출, 지역별 매출 |
| 13~16 | Q1~Q4영업이익 | 연영업이익 부재 시 대체 산출 |
| 17 | **연영업이익** | 총 영업이익, 법인별 차트 |
| 18~19 | 주요제품 / 투자등급 | 표 표시 |

**굵은 표시** = 지표·차트 산출에 사용되는 필수 컬럼

### 6-2. 컬럼 매칭 방식

컬럼명 **완전 일치가 아닌 키워드 포함** 방식으로 탐지한다. 예를 들어 `법인명`은 `법인명` → `법인` → `회사명` 순으로 탐색한다. 파일마다 컬럼명이 미세하게 달라도 동작하도록 하기 위함이다.

### 6-3. 비표준 파일 동작

제공된 나머지 3개 파일은 법인/지역/분기매출 개념이 없는 다른 구조다. 이 경우의 동작은 다음과 같다.

| 기능 | 동작 |
|---|---|
| 데이터 표 | **정상 동작** (헤더 자동 인식) |
| 검색 | **정상 동작** |
| 법인 수 카드 | 행 수로 표시 |
| 매출·이익 카드 | `-` 표시 |
| 차트 3종 | 안내 문구로 대체 |
